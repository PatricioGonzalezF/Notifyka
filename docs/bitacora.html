Qué se hizo, paso a paso

El trabajo tuvo dos fases: Sesión 1, lograr que el proyecto compilara para Android; y Sesión 2, arreglar y robustecer la transcripción de voz.

Sesión 1 · Lograr que compile

Punto de partida. Flutter no estaba instalado. Se generó todo el código fuente (modelo Note, servicios de base de datos / audio / voz / notificaciones, tres pantallas, dos widgets), el pubspec.yaml, el AndroidManifest.xml con permisos y el Info.plist de iOS.

Instalación del entorno. Flutter 3.47.2 stable en C:\src\flutter (primero se clonó por error dentro del propio proyecto; esa copia parcial y rota se borró). Android Studio 2026.1 + SDK. Aceptar licencias. El sdkmanager del SDK no estaba: se instalaron los command-line tools desde el SDK Manager de Android Studio.

Generación. El script bootstrap ejecuta flutter create (crea android/ e ios/), copia el código encima y hace flutter pub get.

Cadena de errores de compilación, resueltos uno a uno

  1. Plugin de Kotlin ausente

    La plantilla de Flutter 3.47 genera android/app/build.gradle.kts con el bloque kotlin { compilerOptions { … } } pero no aplica el plugin de Kotlin. Unresolved reference 'compilerOptions'

    fixAñadir id("org.jetbrains.kotlin.android") al bloque plugins {}.

  2. Core library desugaring

    flutter_local_notifications 18 necesita desugaring de las APIs modernas de Java para poder correr en Android antiguos.

    fixcompileOptions { isCoreLibraryDesugaringEnabled = true } + dependencies { coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.4") }

  3. El binario android.exe del SDK crashea

    El auto-descargador de componentes de AGP 9.1 invoca android.exe (SDK de Android Studio canary), que en este equipo hace stack buffer overrun. exit -1073740791 (0xC0000409)

    fixandroid/gradle.properties → android.builder.sdkDownload=false, para que AGP no lo llame. Los componentes se instalan a mano (pasos 4–6).

  4. NDK 28.2.13676358 no instalado

    Lo exigen speech_to_text y jni (dependencia nativa de record). NDK not configured. Preferred NDK version is '28.2.13676358'

    fixComo sdkmanager fallaba, se descargó el ZIP oficial android-ndk-r28c-windows.zip (748 MB) y se extrajo en Sdk/ndk/28.2.13676358/.

  5. Plataformas Android 34 y 35 no instaladas

    flutter_local_notifications compila contra API 34; jni contra API 35. Failed to find target with hash string 'android-34'

    fixandroid.exe sdk install "platforms/android-34" y "platforms/android-35" — los paquetes chicos sí entraban por esa vía.

  6. CMake 3.22.1

    El módulo jni compila código C++ nativo con CMake. [CXX1300] CMake '3.22.1' was not found

    fixandroid.exe sdk install "cmake/3.22.1" (trae también ninja).

  7. record 5.2.1 con dependencias internas rotas

    pub resolvía record_linux 0.7.2 (viejo) contra record_platform_interface 1.6.0 (nuevo) → firma de método incompatible al compilar el código Dart.

    fixpubspec.yaml → record: ^6.0.0 (resuelve a 6.2.1, conjunto coherente). La API que usa la app no cambia.

  8. zonedSchedule exige un parámetro

    En flutter_local_notifications 18.x, uiLocalNotificationDateInterpretation sigue siendo obligatorio (se quitó en la 19).

    fixPasar UILocalNotificationDateInterpretation.absoluteTime.

Verificación. flutter build apk --debug ✓. Instalado en un emulador Pixel / Android 15. Probado y funcionando: lista de notas por fecha, FAB → grabación (audio + timer + estado), guardar → nota en SQLite, persiste al cerrar y reabrir la app, pantalla de detalle.

Sesión 2 · Arreglar la transcripción

Síntoma: la transcripción salía vacía y sin explicación.

Mejoras de robustez en el código

  1. Resolución de idioma con fallback

    Antes: localeId: 'es_ES' fijo. Ahora speech_service.dart consulta _speech.locales() y elige el mejor disponible: es_ES → cualquier es_* → idioma del sistema → en_* → el primero. Expone resolvedLocaleId, añade callbacks onError, envuelve listen() en try/catch y registra un log de diagnóstico en debug.

  2. Feedback honesto en pantalla

    Antes: si el dictado fallaba, el recuadro quedaba vacío. Ahora record_screen.dart muestra un aviso que traduce el estado real a lenguaje claro (no disponible / sin idioma instalado / error concreto) y deja seguir grabando solo el audio.

  3. Auto-reanudación de la sesión de dictado

    speech_to_text cierra la sesión tras ~30 s de silencio o al fijar un resultado. Antes la transcripción se moría en silencio. Ahora se reabre con 700 ms de retraso y se rinde tras 3 errores seguidos o un error fatal. (Un intento intermedio reabría sin retraso y provocó un bucle de error_too_many_requests — corregido con el debounce y un tope de reintentos.)

  4. Convivencia entre grabar y transcribir

    record por defecto pausaba la grabación al cederle el foco de audio al reconocedor del sistema. audio_service.dart ahora usa RecordConfig(audioInterruption: none, androidConfig: AndroidRecordConfig(audioSource: mic, manageBluetooth: false)) para que el archivo y la transcripción funcionen a la vez en un teléfono real.

Por qué el emulador no transcribe (es infraestructura del emulador, no el código)

  1. El paquete de voz estaba deshabilitado

    com.google.android.tts tenía enabled=0, así que el RecognitionService por defecto no podía enlazarse. Bind to system recognition service failed with error 10

    fixadb shell pm enable com.google.android.tts

  2. El emulador silencia el micrófono

    El emulador pone la entrada de audio en cero salvo que se arranque con -allow-host-audio («Otherwise, zeroes out audio»). Se relanzó con esa opción, que enruta el micrófono del PC.

  3. Falta el modelo de voz y falta cuenta Google

    El modelo offline es-ES no está descargado, y el reconocedor online devuelve HTTP 401. Los dos caminos exigen iniciar sesión con una cuenta de Google en el emulador («Sign in to make the Google Assistant yours»). Sin cuenta, no hay reconocimiento — y esa cuenta es tuya, no la pone el asistente.

Cómo probar la voz de verdad. Opción A (recomendada): flutter run con tu teléfono conectado por USB — ya tiene cuenta Google, español y stack de voz completo; abre Notify, toca el micrófono y habla. Opción B: en el emulador, añade tu cuenta Google, descarga «Offline speech recognition → Español (España)», relanza con -allow-host-audio y habla al micrófono del PC.
